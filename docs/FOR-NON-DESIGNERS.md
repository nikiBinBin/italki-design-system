# 用 AI 生成符合设计规范的界面（非设计师版）

你不需要读完整套设计文档，也不需要会画图。照下面三步做，AI 会用 italki 已有的
组件帮你把界面搭出来，而且不会自己发明不存在的东西。

---

## 第一步：先去看有什么

**https://design.italkiux.com/**

左侧按分类列出了所有可用的组件（按钮、表单、日历、卡片、弹窗……）和产品模板。
每个组件都能看到它的各种状态：正常、加载中、出错、禁用、空数据。

先花五分钟翻一下。你会发现你要的东西大概率已经存在 —— 这一步能省掉后面大量返工。

---

## 第二步：把下面这段整段复制给 AI

把 `【】` 里的内容换成你的情况，其余原样保留。

```
请先读取并遵守这份设计系统指令包：
https://design.italkiux.com/AI.md

然后按它的规则，为我生成下面这个需求的界面方案。

User Story:
作为【什么情况下的什么用户】，我想要【完成什么任务】，以便【达到什么结果】。

Object To Create Or Improve:
【新页面 / 在现有页面上加东西 / 一个区块 / 一个弹窗 / 流程中的一步】

Current Context:
【这个东西出现在产品的什么地方，用户从哪儿来】

Must-Have Information:
【必须显示出来、否则这事就办不成的信息】

Primary Action:
【用户在这儿最主要要做的那一件事】

Constraints Or Special Notes:
【业务限制 / 要复用的现有页面 / 主要在手机还是电脑上用 /
  哪些信息可以折叠起来 / 有哪些数据可能拿不到】

如果我上面哪一项没写清楚、而且会影响你的判断，请先问我一个问题，
不要自己猜。
```

**填不满也没关系** —— 但 `Primary Action`（主要行动）和 `Must-Have Information`
（必须显示的信息）这两项尽量写清楚，它们决定了整个界面的结构。

---

## 第三步：检查 AI 的产出

AI 应该会给你一份带这些内容的方案。重点看三处：

| 看什么 | 你要确认的事 |
| --- | --- |
| **Component Selection Trace** | 它用的是现有组件，不是自己编的新组件 |
| **Visible Element Evidence Check** | 每个出现在界面上的东西都说得出「为什么它在这」 |
| **Compliance Status** | 有没有 `Needs Decision` 或 `Blocked` |

**看到 `Needs Decision` 或 `Blocked` 是好事**，不是出错 —— 说明 AI 遇到了需要
你或设计师定的问题，它没有硬猜。把那几项补掉再让它继续。

反过来，如果 AI 给的东西**又漂亮又完整、一个问题都没提**，反而值得警惕：
八成是它把不确定的地方自己编了。

---

## 几条你不用记但最好知道的红线

AI 会自动遵守，但你评审时看到下面这些情况可以直接打回：

- **一个页面只能有一个红色按钮**。如果出现两个及以上红色主按钮，一定是错的
- 筛选、排序、翻页这类操作**不能用红色**
- 列表里重复出现的卡片，按钮不该个个都是实心高亮
- 同一条信息（课程、时间、价格）**只能有一个地方负责显示**，不该在页面上重复
- 界面上不该出现组件名、规则编号、说明文字这类给内部看的东西

---

## 什么时候需要找设计师

这套流程覆盖的是「用现有组件组装常规功能」。下面这些情况请拉设计师进来：

- 需要**全新的视觉方向**，不是在现有风格里组装
- 需要一种**现有组件表达不了的交互**（AI 会标成 `Blocked`，那就是信号）
- 涉及**品牌关键页面**（首页、落地页、活动页）
- AI 反复提示某个组件契约有缺口 —— 那需要设计师决定是否扩展设计系统
